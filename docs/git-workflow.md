# Git-воркфлоу курсу — читати ПЕРЕД комітом / пушем / створенням PR

Обов'язкове читання перед будь-яким `git commit`, `git push` або створенням Pull Request.
Правила стосуються домашніх завдань (ДЗ) курсу з agentic engineering.

2️⃣ Кожне ДЗ — окрема фіча-гілка від main у вашому форку.

3️⃣ Pull Request створюєте у СВІЙ форк, у свій `main` — не в оригінальний стартовий репозиторій, з якого форкали. Це принципово: у оригінальний (upstream) репозиторій ви змерджити нічого не зможете. Якщо продовжувати відкривати PR туди, зміни просто накопичуватимуться некуди не мержачись, і під кінець курсу у вас буде один PR на 300-500 змінених файлів — перевірити таке нереально, і сенсу в цьому нема.

4️⃣ Після кожної домашньої роботи — мержте PR у `main` свого форку. Далі на наступне ДЗ знову створюєте нову гілку від оновленого main, і знову окремий PR туди ж, у свій форк.

Так у вас на кожен PR буде видно тільки зміни саме цього домашнього завдання (diff проти вашого ж `main`) — і мені, і вам буде зручно перевіряти й переглядати. Ще раз форкати стартер повторно не треба — форк робите один раз.

## Чек-лист перед PR

- [ ] Працюю у фіча-гілці від актуального `main` свого форку (не в `main`, не в гілці від upstream).
- [ ] База PR = `main` **мого форку**, а не upstream-репозиторій.
- [ ] Diff містить зміни лише цього ДЗ.
- [ ] Після ревʼю — мерджу PR у свій `main`, і наступну гілку беру вже від оновленого `main`.
